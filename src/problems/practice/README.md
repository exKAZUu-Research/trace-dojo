Practice programs are independently authored teaching examples reserved for ungraded practice. Keep them out of assignment pools. Review new practice and assignment templates against both banks: renamed identifiers, changed literals, formatting, or decorative statements alone do not make an assignment example suitable for practice. Preserve matching Java and instrumented behavior and validate both execution paths when editing a template.

Each configured lecture contains three elementary patterns with three fixed, learner-visible variants each. Keep concrete variants deterministic and free of hidden numeric placeholders. Selection excludes the immediately preceding question ID; it does not guarantee that all nine questions appear before one repeats.

Practice IDs include the bank version, course, lecture, descriptive family, and variant (for example, `practiceEasyV1Beginner1L1TerminalTurnV1`). Do not change a published ID's source in a way that reinterprets saved execution state. The explicit retirement manifest records the replaced bank's IDs and original course/lecture membership without retaining their source. Starting practice skips recognized retired regular sessions with valid regular state, preserving their rows and submissions; their mutation requests require reloading into a current session.
